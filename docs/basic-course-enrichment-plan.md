## 2. แนวทางการเพิ่มความละเอียด (Guidelines)

หลักการที่ใช้กับทุกบท — ทำต่อให้สม่ำเสมอ:

1. **เติมเฉพาะของที่ใช้จริงในงาน** — ถามว่า "ความรู้นี้ช่วยให้ทำงาน/ผ่านสัมภาษณ์ได้ไหม" ถ้าไม่ ข้าม
2. **อย่า bloat** — บทไหนแน่นแล้ว เติมแค่ส่วนที่ขาดจริง อย่าฝืนเพิ่มให้ยาว (over-engineering)
3. **ทุกหัวข้อควรมี**: callout "กับดักที่เจอบ่อย" (`warn: true`) + เชื่อม "ในงานจริงใช้ยังไง"
4. **โค้ดตัวอย่างรันได้จริง** + คอมเมนต์ไทย + ผลลัพธ์ต่อท้าย
5. **เชื่อมไปคอร์สเชิงลึก** — ของที่ลงลึกกว่านี้ให้บอกว่า "เรียนต่อในคอร์สเขียนโปรแกรมเชิงลึก" (อย่าสอนซ้ำให้ลึกเท่ากัน)
6. **ทุกหัวข้อต้องมีแบบฝึกหัด** (บทที่ยังไม่มีให้เพิ่ม)
7. **build ทุกครั้งหลังแก้แต่ละบท**: `bun run build` ต้องผ่านก่อนถือว่าจบ
8. วิธีแทรก: ใช้ Edit แทรก block ใหม่ก่อน `{ t: "h2", c: "สรุปหัวข้อนี้" }` ของหัวข้อนั้น แล้วเติม bullet ในสรุปให้สอดคล้อง

## 3. งานที่เหลือ — ทำให้ครบทุกข้อ (Required TODO)

> ยืนยันแล้วว่าทุกข้อด้านล่างเป็น "ของที่ใช้จริงในงาน" → **ทำให้ครบทุกข้อ** ไม่ใช่ตัวเลือก
> (ติ๊ก ✅ หน้าแต่ละข้อเมื่อทำเสร็จ เพื่อให้ session ถัดไปรู้ว่าค้างตรงไหน)

### บทที่ 5 — OOP (`oop-basics.ts`)

**`oop-class`**
- [ ] `__str__` / `__repr__` — print object ให้อ่านรู้เรื่อง (ใช้จริงบ่อยมาก)
- [ ] class attribute vs instance attribute (ต่างกันยังไง + กับดัก mutable class attribute)
- [ ] `@property` เบื้องต้น (getter/setter แบบ pythonic)
- [ ] เกริ่น `@dataclass` (ลดโค้ด boilerplate) → ลิงก์ลงลึกคอร์สเชิงลึก

**`oop-pillars`**
- [ ] `super().__init__()` — เรียก constructor ของ parent ตอนสืบทอด
- [ ] ตัวอย่าง method override ชัด ๆ (ลูกเขียนทับ method แม่)
- [ ] abstraction ด้วย abstract method เป็นรูปธรรม (`ABC` / `@abstractmethod`)

**`oop-relationships`**
- [ ] หลัก "favor composition over inheritance" + ตัวอย่างที่ inheritance ใช้ผิด
- [ ] callout กับดัก: inheritance ลึกหลายชั้นทำให้แก้ยาก

**`oop-design`**
- [ ] เชื่อมไป SOLID (บอกว่าลงลึกในคอร์สเขียนโปรแกรมเชิงลึก)
- [ ] dunder methods ที่เจอบ่อย: `__len__`, `__eq__` (+ ตัวอย่าง)
- [ ] เมื่อไรใช้ฟังก์ชันธรรมดาแทน class (อย่า OOP เกินจำเป็น)

### บทที่ 6 — เว็บ/API/SQL (`web-api-db.ts`)

**`web-how`**
- [ ] request/response headers + body คืออะไร
- [ ] อ้างอิง HTTPS (มีใน cs-internet แล้ว) + idempotent ของ GET/PUT

**`web-api`**
- [ ] query parameters (`?q=...`)
- [ ] ส่ง POST พร้อม body (json=)
- [ ] auth header / API key
- [ ] ⚠️ เช็ค `status_code` / `raise_for_status()` + `try/except`
- [ ] เกริ่น rate limit

**`web-sql`**
- [ ] `WHERE` / `ORDER BY` / `LIMIT`
- [ ] JOIN เบื้องต้น (inner join 2 ตาราง)
- [ ] primary key / foreign key
- [ ] ⚠️⚠️ SQL injection + parameterized query (`?` placeholder) — สำคัญมาก
- [ ] เกริ่น index (ทำไมค้นเร็วขึ้น)

**`web-fullstack`** (บางสุด — 8 blocks ไม่มีแบบฝึกหัด → เสริมมากสุด)
- [ ] เพิ่มแบบฝึกหัด (ตอนนี้ไม่มี)
- [ ] ขยาย flow การทำงานจริง + tech stack ให้ละเอียด
- [ ] เกริ่น deployment (เอาแอปขึ้นออนไลน์)
- [ ] ⭐ ลิงก์ไปคอร์สเขียนโปรแกรมเชิงลึก เป็นทางต่อยอด

> 🎯 ลำดับการทำที่แนะนำ (ทำครบทุกข้ออยู่ดี): `web-fullstack` (บางสุด) → `web-sql` (injection สำคัญ) → `web-api` → `oop-class` → `oop-pillars` → `oop-relationships` → `oop-design` → `web-how`
